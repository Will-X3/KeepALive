Add live video preview to the business dashboard

Backend
- Stream.playbackUrl: where the worker is currently serving its HLS
  output. Reported by the worker on every heartbeat, stored as-is.
  Deliberately only reachable when the worker and viewer share a
  network today — not a production playback path for a remote camera,
  just what's needed for local dev/testing right now.
- Fix: GET /api/businesses/:id never attached the business's locations
  (only /api/businesses/mine did), so the business detail page always
  showed "no locations" regardless of what actually existed in the
  database. Found while testing the camera flow end-to-end, not by
  inspection.

Vision pipeline
- playback_server.py: the worker now serves its own HLS output over
  plain HTTP (bound to all interfaces, so another device on the LAN
  can reach it), with correct MIME types for .m3u8/.ts and CORS
  headers on every response.
- Fix: the playback server had no OPTIONS handler at all. hls.js can
  send a CORS preflight (e.g. when using Range requests for segments),
  and Python's base HTTP handler doesn't answer OPTIONS by default —
  every real browser player would have failed even though a plain curl
  GET worked fine, which is exactly what testing showed before this
  fix went in.
- Worker reports its playback URL alongside every heartbeat.

Frontend
- hls.js added; new VideoPlayer component (hls.js for Chrome/Firefox,
  native HLS for Safari, a real error state instead of a silently
  broken <video> element).
- Camera cards in the dashboard now show a live preview whenever a
  playbackUrl is present — visible to the owner regardless of whether
  the stream is publicly "Live" yet, since blur happens at the source
  either way, before publicState gates public visibility.
- Cross-location camera monitor explicitly opts out of the preview
  (showPreview=false) since those cards are wrapped in a navigation
  link and a <video> with controls would conflict with click-to-navigate.

Verified
- End-to-end, on a real machine, with a real webcam: camera connect ->
  ingest key -> worker -> blur -> HLS -> live preview rendered in the
  actual dashboard UI. This is the first time the full loop was
  confirmed working outside of mocked/sandboxed testing.
- Playback server's MIME types and CORS headers (including the OPTIONS
  fix) verified directly via curl before the browser-level fix.

Known limitations carried forward
- No video player on the public consumer location page yet — only the
  business dashboard preview. Public page still shows the "Live view
  coming soon" placeholder.
- Playback only works when the worker and viewer share a network.
  Real remote cameras need actual hosting/CDN, not solved here.
